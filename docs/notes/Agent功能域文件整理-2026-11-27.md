# Agent 功能域文件整理

## 1. 整理目标

`internal/agent` 原先同时存在多个只有单个类型或辅助函数的小文件，以及超过 1200 行的 `tool_loop_runtime.go`。本次按功能域重新组织生产代码：减少零散文件，但不把所有声明机械并入既有大文件。

生产 Go 文件由 19 个调整为 10 个。整理只移动声明、合并 import 并执行 gofmt，不修改函数实现、导出契约或调用顺序。

## 2. 最终文件职责

| 文件 | 功能域 | 当前规模 |
| --- | --- | ---: |
| `runtime_types.go` | 普通 Runtime 公共类型、配置、观测契约、错误哨兵和阶段错误 | 176 行 |
| `runtime.go` | 普通 Runtime 构造、Run/Shadow、Eino Chain 及全部 Chain 阶段 | 366 行 |
| `runtime_execution.go` | 两种 Runtime 共享的执行准备、受控模型调用、快照/Prompt 和 Context 辅助 | 313 行 |
| `runtime_observation.go` | Observer、模型用量、成本及运行错误分类 | 186 行 |
| `runstore_recorder.go` | RunStore 生命周期事件、终态和旁路持久化失败处理 | 415 行 |
| `budget.go` | 三级预算、预算控制器、结构化修复预算和 Token 估算 | 399 行 |
| `tool_loop_runtime.go` | ToolLoop 公共契约、生命周期、配置绑定、输出和观测 | 535 行 |
| `tool_loop_models.go` | ToolLoop 的 Analysis、ToolDecision、FinalAnswer 模型阶段 | 345 行 |
| `tool_loop_tools.go` | 工具授权、去重、循环检测、Executor、历史和摘要 | 502 行 |
| `pipeline.go` | 最小 Eino Chain、Graph、输入输出和演示模型 | 211 行 |

## 3. 主要归并关系

- `runtime_errors.go` 并入 `runtime_types.go`，集中普通 Runtime 的公共契约。
- `runtime_stages.go` 并入 `runtime.go`，使固定 Chain 的声明和阶段实现可以在同一文件中阅读。
- `runtime_model_call.go`、`runtime_helpers.go` 并入 `runtime_execution.go`，形成两种 Runtime 共用的执行内核。
- `repair_budget.go`、`token_usage.go` 并入 `budget.go`，统一预算与消耗核算。
- `pipeline_builder.go`、`demo_model.go` 并入 `pipeline.go`，集中最小 Eino 演示域。
- `tool_loop_types.go`、`tool_loop_errors.go` 并入 `tool_loop_runtime.go`。
- 原 `tool_loop_runtime.go` 中的模型阶段移至 `tool_loop_models.go`，工具执行及历史处理移至 `tool_loop_tools.go`。
- `loop_detection.go` 并入 `tool_loop_tools.go`，与重复调用检测和工具摘要放在同一功能域。

## 4. 保留的边界

Observer 与 RunStore 继续分开：前者负责运行指标和错误分类，后者负责持久化事件和存储失败语义。普通 Runtime 与 ToolLoopRuntime 也继续保留各自公开入口，不因共享内部实现而合并固定 Chain 与动态工具循环。

测试文件只在相同功能域内选择性合并：`budget_controller_test.go`、`budget_resolver_test.go`、`budget_observation_test.go`、`repair_budget_test.go` 和 `token_usage_test.go` 已并入 `budget_test.go`，集中覆盖限额解析、控制器、观测、修复消耗和 Token 估算。测试文件由 14 个减少为 9 个，合并后的 `budget_test.go` 为 893 行；测试函数及辅助函数实现不变。普通 Runtime、ToolLoop、RunStore、Pipeline 和 Clock 测试继续独立，`tool_loop_types_test.go` 的后续结构整理不属于本次范围。

## 5. 行为约束

本次没有改变：

- 任何导出类型、函数、方法或错误名称；
- 普通 Runtime 的 Chain、Shadow、灰度、评测和输出语义；
- ToolLoop 的模型决策、授权、去重、Executor 和最终回答顺序；
- 预算、Token、Observer、RunStore 或持久化失败处理；
- Tape、Replay、Checkpoint 和上下文治理范围。

历史计划文档仍保留当时的文件路径，不改写历史。当前共享优化文档已补充最终归并位置。
