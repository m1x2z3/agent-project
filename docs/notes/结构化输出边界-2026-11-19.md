# 结构化输出边界

## 本日目标

第二周第 3 天新增独立的 `internal/structuredoutput` 包，把模型生成的 JSON
转换为可以交给业务代码使用的强类型结果。

本日不接入 HTTP，不修改 `/chat` 和 `/chat/stream`，也不把模型网关改造成
Eino `BaseChatModel`。

## 三种结果类型

### `TaskAnalysis`

用于表示任务分析结果：

- `summary`：任务摘要，不能为空。
- `confidence`：模型对分析结果的置信度，范围为 `0~1`。

### `ToolDecision`

用于表示是否允许进入工具调用阶段：

- `should_call=true` 时，必须提供 `tool_name` 和 `arguments`。
- `should_call=false` 时，不能携带工具调用信息。

这个类型只表达模型的结构化建议，不代表模型已经获得执行工具的权限。
后续仍需要由确定性权限、风险和审批逻辑决定是否真正执行。

### `FinalAnswer`

用于表示最终回答或明确拒答：

- `status=answered` 时必须有 `answer`，不能有 `refusal_reason`。
- `status=refused` 时必须有 `refusal_reason`，不能有 `answer`。
- `citations` 表示回答使用的证据来源；引用的 `source` 和 `location` 不能为空。

## 两层校验

解码流程是：

```text
严格解析单个 JSON 值
  -> JSON Schema 校验
  -> Go 结构体反序列化
  -> 业务语义校验
  -> 返回强类型结果
```

JSON Schema 负责通用结构约束：

- 必填字段；
- 字段类型；
- `confidence` 的数值范围；
- `status` 的枚举值；
- 禁止未知字段；
- 嵌套引用的结构。

业务语义校验负责跨字段规则：

- 工具是否调用与工具名称、参数是否匹配；
- answered 和 refused 是否互斥；
- 文本字段是否为空或只有空白；
- 拒答是否携带了不应该出现的引用或回答内容。

两层校验不能互相替代。Schema 不适合承载所有复杂业务状态，而只依赖
Go 反序列化又会让未知字段、缺失字段和类型错误悄悄进入业务层。

代码中对应的执行顺序是显式拆开的：

```text
validateAndDecode
  -> validator.Validate(instance)  // JSON Schema 结构校验
  -> unmarshalValue(normalized)   // JSON 转 Go 类型
  -> validateValue(value)          // Validate() 业务语义校验
```

## 一次修复边界

原始输出校验失败时，可以调用注入的 `RepairFunc` 一次：

```text
原始 JSON 校验失败
  -> RepairFunc
  -> 完整执行同一套 JSON、Schema 和语义校验
  -> 成功，或确定性失败
```

最多修复一次的原因：

- 避免格式错误导致无限重试；
- 控制模型调用次数、延迟和成本；
- 失败后给上层明确的可观测状态；
- 防止修复过程逐步偏离原始业务约束。

修复函数接收原始字节、失败原因和执行元数据，但错误信息不会回显完整模型
输出、Prompt、API Key 或供应商原始错误。修复后仍非法时不会再次调用修复函数。

## 版本元数据

调用方必须注入并由 `DecodeReport` 原样保留：

```text
provider
model
prompt_version
schema_version
model_config_version
```

当前固定的 Schema 版本为：

```text
task_analysis.v1
tool_decision.v1
final_answer.v1
```

本日只在内存中传递和返回这些元数据，尚未实现数据库持久化、配置发布或历史
快照。后续如果修改字段、Prompt 或模型配置，应升级相应版本并保留兼容策略。

## 与其他层的边界

```text
HTTP Handler
  -> Agent / Workflow
  -> Model Gateway
  -> 模型输出
  -> structuredoutput.Decode*
  -> 确定性业务校验
  -> 工具权限、审批或最终响应
```

- `internal/llm`：负责 OpenAI 兼容 HTTP 和 SSE 协议。
- `internal/modelgateway`：负责供应商选择、路由和供应商无关的调用结果。
- `internal/agent`：负责 Eino 编排。
- `internal/structuredoutput`：负责模型输出的结构化可信边界。
- HTTP 层：负责请求协议和响应协议，不直接依赖本包的内部 Schema 实现。

本包不会授予模型工具权限，不执行工具，不保存运行记录，也不把模型输出直接
当作安全决策。
