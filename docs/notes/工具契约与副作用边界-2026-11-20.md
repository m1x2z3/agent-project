# 工具契约与副作用边界

## 本日目标

第三周第一天建立独立的 `internal/tool/tooling` 工具契约层，只定义工具能力、
调用请求、结果 Envelope、Capability Token 和副作用边界。

本日不实现具体工具，不接入 HTTP、数据库、MCP、RBAC 或 Agent 自动工具循环。

## ToolDecision 与真正执行

`structuredoutput.ToolDecision` 只表示模型提出的调用意图：

```text
should_call
tool_name
arguments
```

它不代表模型已经获得执行权限，也不包含租户、Run 或 Capability Token。

真正执行必须经过确定性边界：

```text
模型 ToolDecision
  -> 严格结构化解析
  -> 工具名称和版本校验
  -> 参数 Schema 校验
  -> 租户和 Run 校验
  -> Capability Token 校验
  -> 权限和资源范围校验
  -> 风险和副作用策略校验
  -> Tool.Execute
```

因此，模型输出不能直接调用工具。

## 工具元数据

`ToolDefinition` 保存工具的稳定契约：

- 名称和版本；
- 描述和权限标识；
- 风险等级；
- 只读、幂等写或不可安全重试写；
- 超时时间；
- 参数 Schema；
- 租户范围；
- 能力标签；
- 是否废弃。

工具版本不是装饰字段。后续工具参数、权限或副作用语义发生不兼容变化时，
必须发布新版本，避免旧 Run 使用错误的执行契约。

## 副作用分类

### 只读工具

只读取文档、Issue、日志或时间等数据，不应修改外部状态。失败通常可以安全
重试，但仍需要租户和资源范围校验。

### 幂等写工具

会修改外部状态，但同一个幂等键重复执行不会产生重复副作用。后续需要结合
幂等键、结果查询或数据库唯一约束实现可靠执行。

### 不可安全重试写工具

可能发送通知、触发部署或修改不可回滚状态。不能因为模型或网络错误就盲目
重试，后续需要审批、结果确认或专门的外部副作用协议。

## Capability Token

Capability Token 是工具执行授权凭证，绑定：

```text
tenant_id
run_id
tool_name
tool_version
resource_scope
expires_at
nonce
```

当前代码只实现令牌声明和确定性校验，不是生产级 JWT，也没有持久化 nonce
防重放存储。后续接入真实身份和 RBAC 后，应由授权服务签发令牌，并在执行
入口验证令牌绑定关系和过期时间。

模型不能生成有效 Capability Token。模型只能提出工具名和参数，授权信息必须
来自确定性控制面或权限服务。

## internal/tool/tooling 与其他层的边界

```text
HTTP Handler
  -> Agent Runtime
  -> ToolDecision
  -> tooling.Invoke
  -> 具体 Tool.Execute
```

- `internal/structuredoutput`：解析和校验模型生成的工具调用意图。
- `internal/tool/tooling`：定义工具契约、调用请求、结果和安全执行边界。
- `internal/tool/registry`：后续负责注册、白名单、版本兼容和工具发现。
- `internal/agent`：后续负责决定何时需要工具以及如何编排调用。
- Eino：后续可以通过 Adapter 接入工具，但不作为权限和副作用边界。
- `internal/modelgateway`：只负责模型调用，不负责工具执行授权。
- HTTP：只负责请求和响应协议，不直接调用具体工具。

本日没有实现具体工具、RBAC、数据库、MCP、审批或自动工具循环。

由于本日尚未实现审批服务，`RiskHigh` 且会产生副作用的工具即使拥有普通权限，
也会在 `tooling.Invoke` 中返回“需要审批”，不会进入 `Tool.Execute`。后续审批
模块需要签发与 Run、租户和工具版本绑定的审批凭证，再扩展执行前置条件。
