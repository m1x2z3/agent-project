# 模型网关边界

## 本日目标

第二周第 2 天建立供应商无关的模型调用边界，不改变现有 HTTP API，也不提前实现
结构化输出、配置版本、灰度、自动重试和降级。

## 调用分层

```text
Agent / 业务层
  -> modelgateway.Router
  -> modelgateway.ModelProvider
  -> OpenAICompatibleProvider
  -> internal/llm.Client
  -> OpenAI 兼容模型服务
```

- `modelgateway`：负责任务路由、供应商选择、统一请求/响应类型、健康状态和错误分类。
- `internal/llm`：负责 HTTP 鉴权、OpenAI 兼容 JSON、SSE 解析和上游错误转换。
- `internal/agent`：负责 Eino 的 Prompt、Model、Lambda、Chain 和 Graph 编排。
- `httpapi`：继续依赖现有 `ChatClient`，本日不把网关类型扩散到 HTTP 契约。

## 路由优先级

```text
ChatRequest.Provider
  -> LLM_ROUTE_<TASK>
  -> LLM_DEFAULT_PROVIDER
```

本日不做自动故障转移。未知供应商、配置不完整或本地健康状态不可用时直接返回
供应商无关的错误分类。

## 配置兼容

旧的单供应商配置仍然有效：

```text
LLM_BASE_URL
LLM_API_KEY
LLM_MODEL
LLM_TEMPERATURE
LLM_MAX_TOKENS
LLM_TIMEOUT
```

多供应商配置使用：

```text
LLM_PROVIDERS=deepseek,kimi
LLM_DEFAULT_PROVIDER=deepseek
LLM_DEEPSEEK_BASE_URL=...
LLM_DEEPSEEK_API_KEY=...
LLM_DEEPSEEK_MODEL=...
LLM_KIMI_BASE_URL=...
LLM_KIMI_API_KEY=...
LLM_KIMI_MODEL=...
```

配置加载后会把默认供应商同步到旧的顶层 `LLM*` 字段，因此已有服务启动入口
仍能正常工作。API Key 只用于构造模型客户端，不进入日志、错误响应或提交记录。

## 健康状态边界

本日的健康检查只检查本地配置是否完整、URL 是否合法、模型和 API Key 是否存在。
不会发起真实模型请求，也不会消耗模型额度。因此 `configured` 表示“配置可用”，
不等价于“供应商当前网络可用”。

## 错误边界

`internal/llm.APIError` 在网关边界转换为统一错误分类：

- `invalid_request`
- `provider_not_found`
- `provider_unavailable`
- `canceled`
- `timeout`
- `network_error`
- `upstream_error`

网关错误保留状态码和上游 request ID 等排障元数据，但不暴露供应商返回的原始错误
消息，避免业务层依赖供应商协议或敏感错误文本。
