# 周四：Go 基础与模型调用链路

## 1. Context

`context.Context` 用于在一次调用链中传递取消信号、截止时间和少量请求范围数据。它不是普通配置容器，也不应该保存业务参数或大型对象。

当前项目使用 HTTP 请求的 Context 贯穿模型调用：

```go
result, err := h.client.Chat(r.Context(), messages)
```

`llm.Client.Chat` 会把这个 Context 绑定到模型 HTTP 请求：

```go
request, err := http.NewRequestWithContext(ctx, http.MethodPost, endpoint, body)
```

因此客户端断开、上游请求超时或父 Context 被取消时，模型请求也会尽快停止。

常见 Context 关系：

```text
父 Context
  -> WithCancel：调用 cancel 主动取消
  -> WithTimeout：超过截止时间自动取消
  -> WithDeadline：到达指定时间自动取消
```

检查方式：

```go
if err := ctx.Err(); err != nil {
    return err
}
```

- `context.Canceled`：主动取消或父 Context 取消。
- `context.DeadlineExceeded`：超时或截止时间已到。

当前项目在 Handler 和 LLM Client 两层检查 Context。Handler 负责不向已断开的客户端写响应，LLM Client 负责不发送已经取消的模型请求。

## 2. 错误包装与判断

使用 `%w` 包装错误，可以保留原始错误链：

```go
return fmt.Errorf("send llm request: %w", err)
```

使用 `errors.Is` 判断已知错误：

```go
if errors.Is(err, context.DeadlineExceeded) {
    // 映射为 504
}
```

使用 `errors.As` 提取结构化错误：

```go
var apiErr *llm.APIError
if errors.As(err, &apiErr) {
    // 映射为 502
}
```

当前错误处理的原则：

- 底层补充上下文，但不丢失原始错误。
- 调用方使用 `errors.Is/As`，不依赖错误字符串。
- HTTP 层把内部错误转换成稳定的客户端错误结构。
- API Key、完整消息和其他敏感数据不放入错误响应。

## 3. HTTP Handler

`http.Handler` 的核心方法是：

```go
ServeHTTP(http.ResponseWriter, *http.Request)
```

当前项目的 Handler 负责四件事：

1. 根据路径和 HTTP 方法分发 `/health` 与 `/chat`。
2. 限制请求体大小并解析 JSON。
3. 校验消息数量、角色和内容。
4. 调用 `ChatClient`，将结果或错误转换为 JSON 响应。

Handler 不直接依赖具体的 `llm.Client`，而是依赖最小接口：

```go
type ChatClient interface {
    Chat(context.Context, []llm.Message) (llm.ChatResponse, error)
}
```

这样可以在单元测试中注入 fake client，稳定覆盖模型成功、超时、APIError、内部错误和 Context 取消，而不需要真实调用模型服务。

## 4. 模型调用链路

```text
curl/Postman
  -> http.Server
  -> httpapi.Handler
  -> 请求体大小限制和 JSON 解析
  -> messages 参数校验
  -> ChatClient 接口
  -> llm.Client.Chat
  -> OpenAI 兼容模型服务
  -> ChatResponse 或 APIError
  -> HTTP 成功响应或统一错误响应
```

成功路径：

1. 客户端发送 `POST /chat`。
2. Handler 校验请求并转换为 `[]llm.Message`。
3. `llm.Client` 组装模型请求，添加 Bearer Token 和模型配置。
4. 上游返回 `ChatResponse`。
5. Handler 取第一个候选消息，包装成项目业务响应。

失败路径：

- 参数或 JSON 错误：`400 invalid_request`。
- 模型请求超时：`504 model_timeout`。
- 模型服务返回 `APIError`：`502 model_error`。
- 其他内部错误：`500 internal_error`。
- 客户端主动取消：停止处理，不强行写响应。

## 5. 面试回答提纲

### 为什么模型客户端要单独封装？

将供应商协议、鉴权、超时、响应解析和错误转换集中在 `llm.Client`，让 HTTP 层只处理业务请求和响应。未来切换 OpenAI 兼容供应商时，业务层不需要跟着修改。

### 为什么 Handler 依赖接口？

Handler 只需要 `Chat` 能力，不应该绑定具体实现。接口让测试可以注入 fake client，隔离网络和模型服务，也为后续替换实现保留空间。

### Context 取消后如何停止处理？

HTTP 请求 Context 传入模型客户端，模型请求使用 `NewRequestWithContext`。Handler 在调用前后检查 Context；收到取消后直接返回，不再写响应。

### 为什么使用 `errors.Is/As`？

错误经过多层包装后，字符串会变化。`errors.Is` 能判断错误链中的固定错误，`errors.As` 能提取 `APIError` 等结构化错误，从而稳定完成错误映射。

### 为什么统一错误结构？

客户端不需要为每个接口设计不同的错误解析逻辑；日志保留内部细节，响应只暴露稳定的 `code`、`message` 和 `request_id`，便于前端处理和问题追踪。
