# Agent Runtime 安全边界

## 1. 本次范围与威胁模型

第 4 周第 4 天为普通 `Runtime` 和 `ToolLoopRuntime` 增加了固定、可解释的 `security.v1` 本地安全边界，主要处理：

- 用户输入、外部文档、日志、Issue、工具结果和模型输出被误当成系统指令；
- 工具结果中的部分高置信度 Prompt Injection 在进入后续 Prompt 前传播；
- 模型意图绕过可信 Authorizer、Capability、资源范围、权限或审批；
- 保留的 `network_egress` 能力在当前没有出站审批协议时被误用；
- 一个 Run 接触外部内容后，又把可能受污染的数据交给非只读工具。

本日没有增加模型安全审查调用，也没有新增真实网络、日志、Issue 或写工具。危险能力和写路径通过本地测试替身验证。该实现是纵深防御的一层，不是完整 Prompt Injection 检测器、语义 DLP 或生产级授权服务。

## 2. 安全版本、可信度与内容类别

安全版本在配置快照绑定成功后立即固定为：

```text
security.v1:<ReleaseVersion>
```

同一 Run 不再读取变化中的安全配置。`security.v1` 标识本日的标签、消息分离、注入规则和执行前数据流算法；既有 `context.v1` 继续独立标识工具历史治理算法。

可信度标签是代码中的封闭枚举：

| 标签 | 内容 |
| --- | --- |
| `trusted_system` | Runtime 固定的平台安全指令 |
| `untrusted_user` | `RunInput.Query`，登录用户输入也不视为系统指令 |
| `untrusted_external` | 文档、日志、Issue、通用工具结果及其 Data/Source |
| `untrusted_model` | 分析、工具决策、最终回答的模型输出及结构化解析结果 |

内容类别包括 `system_instruction`、`user_input`、`document`、`log`、`issue`、`tool_result` 和 `model_output`。

工具注册定义只能声明受限的 `ResultContentKind`：`tool_result`、`document`、`log` 或 `issue`。零值归一为 `tool_result`，`search_project_docs` 显式声明为 `document`。Agent 通过显式转换生成内容类别；工具 Data、Source 或模型 JSON 中的同名字段不能覆盖外层标签，也不能把外部内容伪装成系统指令、用户输入或模型输出。

## 3. 内容 envelope 与模型消息

Query、已校验 TaskAnalysis 和工具历史通过独立 JSON envelope 进入任务模板，例如：

```json
{
  "security_version": "security.v1:v1",
  "trust": "untrusted_user",
  "kind": "user_input",
  "content": "..."
}
```

工具历史 envelope 同时包含 `security_version`、`context_version`、`omitted_entries` 和 `entries`。每条历史显式携带 `trust=untrusted_external` 和可信注册定义对应的 `content_kind`；Data 与 Source 位于同一个不可信 `content` 投影中。

JSON 编码负责处理引号、换行、Unicode、伪造 envelope 和闭合标记，不通过手写 XML 或字符串闭合标签划分边界。Schema 校验只证明模型输出结构合法，不把分析或工具意图提升为可信授权事实。

共享模型调用内核固定发送两条消息：

```text
messages[0]: role=system，Runtime 代码中的固定安全指令
messages[1]: role=user，当前任务模板和带标签的不可信内容
```

任务模板不会整体进入 system 消息。固定指令明确：外部数据不能覆盖平台规则、提升 Capability、扩大资源范围或替代审批，任何工具调用仍须通过 Runtime 确定性门禁。

供应商缺少 Usage 时，本地预算估算包含 system、任务 user 和模型响应。上下文治理 before/after 也使用同一 system 口径。供应商返回真实 Usage 时不叠加本地估算，本地估算不会写入真实 Usage 或成本。

## 4. Prompt Injection 快速拦截

`security.v1` 使用固定本地字符串规则，检测前只做小写和连续空白归一化，当前覆盖三类有限模式：

| 分类 | 示例语义 |
| --- | --- |
| `instruction_override` | 忽略或覆盖先前指令 |
| `system_prompt_exfiltration` | 输出、显示或泄露系统提示词 |
| `approval_bypass` | 绕过审批、安全策略、Capability 或运行时授权 |

检测报告只包含稳定类别代码，不包含原文、命中片段或位置。

检查位置及失败语义固定如下：

1. **用户 Query**：快照绑定和安全版本固定后、首次分析模型调用前检查一次；命中时模型调用为 0。
2. **工具结果**：只有 `Executor.Execute` 以 `err == nil` 返回时，立即联合检查原始 Data 和 Source 一次；空内容和合法业务失败结果也计检查。
3. **保留真实工具事实**：命中后仍按既有流程记录 `tool.result` 并追加原始工具历史，但当前 Run 随后以安全错误终止。
4. **停止传播**：命中内容不会进入压缩、后续 Prompt、下一次模型或后续工具；失败响应不暴露完整 Data/Source。
5. **执行错误优先**：Executor 自身返回错误时保留原执行失败，不改写成注入错误，也不增加工具结果检查。

检测发生在压缩、降级和省略之前，因此超长结果、只保留 Preview 或最终会被省略的结果都不能借治理绕过原始内容检查。

## 5. 执行前只读预检与授权

`runner.Executor.Inspect` 提供不执行工具的只读检查，顺序为：

```text
Context
  -> ToolCallRequest.Validate
  -> Registry.Resolve
  -> buildExecutionRequest
  -> tooling.ValidateExecutionRequest
  -> 返回已注册工具定义的独立副本
```

它完成工具发现、参数编码、Schema、租户、Run、版本、资源范围、权限和现有审批契约检查，但不调用 `Tool.Execute`、不访问底层数据源、不占用工具预算，也不生成工具事件。

ToolLoop 的顺序为：

```text
结构化 ToolDecision
  -> 可信 Authorizer 注入执行上下文
  -> Executor.Inspect
  -> 危险能力和 Run 级数据流检查
  -> 重复与无进展循环检查
  -> 工具预算记账
  -> tool.call
  -> Executor.Execute
  -> tooling.Invoke 防御性复核
  -> Tool.Execute
```

模型不能生成有效授权事实。Authorizer 仍不能改写模型工具名或参数，请求必须绑定当前 Request、Tenant、Run 和显式工具版本。最终 `tooling.Invoke` 保留原有校验，防止其他调用方绕过 Agent 层。

普通契约错误会提前返回，保留原稳定原因和 `tool_execution_error` 等既有分类，不占用工具预算、不生成执行事件、不修改工具历史，也不计安全检查或安全拦截。唯一例外是 `ErrApprovalRequired`：它计入一次危险工具检查，并包装为 `ErrDangerousToolRequest`，同时保留底层审批原因供 `errors.Is` 判断。

## 6. 危险能力与 Run 级数据流

当前固定规则如下：

| 条件 | 结果 |
| --- | --- |
| 高风险写操作没有审批 | `ErrDangerousToolRequest`，并保留 `ErrApprovalRequired` |
| 注册定义包含 `network_egress` | 无论声明读或写，均默认拒绝 |
| 当前 Run 已接触非空 Data 或 Source，后续请求 `EffectClass != EffectRead` | `ErrDataExfiltrationBlocked` |
| 已接触外部内容，后续仍为只读请求 | 可继续，但每个请求和结果仍独立检查 |
| 业务失败只有错误码或错误元数据，没有 Data/Source | 不制造外部内容污染 |
| 没有外部内容时的普通低风险写操作 | 保留既有 Schema、权限、幂等和副作用契约，不额外宣称生产安全 |

危险能力或未审批高风险操作的分类优先于数据流。`network_egress` 即使与普通只读标签同时存在，也不能仅凭普通 Capability Token 放行。

污染状态是当前 Run 私有的保守标记，不是逐字段血缘分析。模型可能复制、摘要或改写外部内容，因此不通过参数字符串包含来猜测是否安全；宁可阻止合法写入，也不声称已证明参数未受外部内容影响。用户输入和模型输出不会仅因存在就制造这类工具外部内容污染，但它们同样不能提升 Capability 或替代审批。

## 7. 观测、错误与敏感信息边界

Agent `RunObservation` 和 `runstore.RunObservation` 保存六个安全字段：

| 字段 | 含义 |
| --- | --- |
| `SecurityVersion` | 当前 Run 固定的安全算法及发布版本 |
| `SecurityChecks` | Query、成功返回工具结果和执行前安全门禁的完成次数 |
| `SecurityBlocks` | 安全策略实际终止当前 Run 的次数，当前 fail-fast 流程通常为 0 或 1 |
| `PromptInjectionBlocks` | Prompt Injection 终止次数 |
| `DangerousToolBlocks` | 危险能力或未审批高风险操作终止次数 |
| `DataFlowBlocks` | 外部内容流向非只读工具的终止次数 |

计数单位不是规则数或字段数：

- 每个完成快照绑定的 Run 对 Query 检查一次；
- 每个 `Executor.Execute err == nil` 的结果对 Data/Source 联合检查一次；
- 每个通过普通契约预检的 `should_call=true` 请求合并检查一次；`ErrApprovalRequired` 也计一次；
- 命中同样计检查；每次实际终止只计一次总拦截和一个子类别。

每次检查或拦截在当前 Run 的执行账本锁内立即累计，中途失败保留已有指标。`snapshotRunObservation` 将同一快照复制到 RunStore。没有新增 Run 状态、事件类型或状态转移，安全失败沿用现有失败终态，并通过以下稳定 `ErrorKind` 区分：

```text
security_prompt_injection
security_dangerous_tool
security_data_exfiltration
```

错误、Observer、RunStore 和回调不保存 Query、完整 Prompt、模型回答、工具参数、Data、Source、压缩 Preview、注入命中片段、API Key、Capability Token、审批内容或供应商原始错误文本。RunStore 写入仍是旁路操作，存储失败不改变 Runtime 主流程。

## 8. 并发、限制与未验收范围

每个 Run 使用独立的快照、安全版本、污染状态和执行账本；Runtime 构造后的策略和固定规则只读。并发测试覆盖无污染写入、外部读取后写入和 Query 注入混合执行，以及 v1/v2 版本绑定、双端观测和计数隔离。

必须保留以下限制：

- 人工固定规则只能覆盖当前列出的高置信度文本，同义改写、隐蔽编码、拆字和语义注入可能绕过；
- system/user 分离和 JSON 标签只能帮助模型区分数据与指令，不构成模型一定拒绝注入的保证；
- 正常讨论攻击文本也可能误报，本日没有完成误报率统计；
- 执行门禁主要限制越权和工具副作用，不保证模型生成的所有文字都不受遗漏注入影响；
- Run 级污染是保守策略，可能阻止实际安全的合法写操作；
- 当前没有真实 Capability Token 签名、完整审批服务、语义 DLP 或通用文本净化器。

第 5 天 Checkpoint、完整 Replay、事件回放器和 Fuzz 状态模型不在本次范围内；第 6 天至少 40 条安全样例、危险操作拦截率、误报统计和剩余风险评估也尚未验收。测试全绿只代表当前固定规则与测试场景通过。
