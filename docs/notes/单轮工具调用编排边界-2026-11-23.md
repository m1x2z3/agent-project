# 单轮工具调用编排边界

## 本日目标

第三周第 4 天新增 `internal/tool/runner`，把模型生成的工具调用意图转换为
一次受控的单轮工具执行。

本日只实现单次调用编排，不实现自动工具循环、多工具并行、MCP、RBAC、
审批服务、数据库、自动重试或自动降级。

## 包职责

```text
internal/structuredoutput
  -> 解析并校验模型 ToolDecision

internal/tool/runner
  -> 接收 ToolDecision 和可信调用上下文
  -> 显式解析工具版本
  -> 构造工具层执行请求
  -> 编排一次 tooling.Invoke

internal/tool/registry
  -> 按工具名称和版本发现工具

internal/tool/tooling
  -> 参数 Schema、租户、Run、Capability Token、权限和副作用边界
  -> 调用具体 Tool.Execute

internal/tool/readtools
  -> get_current_time、search_project_docs 等具体工具
```

## 调用链

```text
模型 ToolDecision
  + 外部注入的工具版本、租户、Run、请求 ID、资源范围和 CapabilityToken
  -> runner.ToolCallRequest
  -> runner.Executor.Execute
  -> ToolCallRequest.Validate
  -> Registry.Resolve
  -> buildExecutionRequest
  -> tooling.Invoke
  -> Tool.Execute
```

`ToolDecision` 只表示模型的调用意图，不能携带有效授权。工具版本必须由模型
之外的可信调用方显式提供，`runner` 不根据注册中心列表推断“最新版本”。

## `ToolCallRequest` 和 `Executor`

`ToolCallRequest` 是一次调用所需的数据对象，包含：

- 模型的 `ToolDecision`；
- 外部指定的工具版本；
- `TenantID`、`RunID` 和 `RequestID`；
- 资源范围；
- Capability Token；
- 幂等键。

`Executor` 是一次调用的编排器。它不保存工具定义副本，也不实现权限策略；
它只把请求依次交给注册中心和 `tooling.Invoke`。

`resolvedTool` 表示注册中心根据工具名称和显式版本解析出的
`registry.RegisteredTool`，其中包含工具定义和工具实例。

## 两层校验

`runner.ToolCallRequest.Validate` 是进入编排器的前置校验，重点确认：

- 模型确实请求调用工具；
- 请求 ID、租户 ID、Run ID 和工具版本存在；
- Capability Token 未过期；
- Token 的租户、Run、工具名和版本与请求绑定一致；
- 请求资源在 Token 资源范围内。

`tooling.Invoke` 是最终执行门禁，继续校验：

- 工具定义；
- 参数 JSON Schema；
- 权限；
- 租户范围；
- 资源范围；
- 高风险写操作的审批要求；
- 工具结果 Envelope。

两层校验不是重复实现同一职责。前者保证编排输入完整，后者保证任何进入
具体工具的请求都经过统一安全边界。

## Context 传播

`Executor.Execute` 首先检查 Context。已经取消的请求不会继续解析工具；
通过前置检查后，Context 原样传递给 `tooling.Invoke` 和 `Tool.Execute`。
工具内部或数据源可以继续响应取消和超时。

## 当前边界

当前实现不负责：

- 自动决定是否继续调用模型；
- 多轮工具调用；
- 多工具并行；
- 工具重试、降级或幂等执行；
- Capability Token 签发、JWT、RBAC 和 nonce 防重放存储；
- 审批系统；
- 数据库和持久化注册中心；
- HTTP API 或 Agent Runtime 接入。

后续接入 Agent Runtime 时，Runtime 可以先解析
`structuredoutput.ToolDecision`，再把可信上下文注入 `ToolCallRequest`，
最后调用 `Executor.Execute`。当前 `internal/agent/runtime.go` 不依赖
`runner`，因此现有两阶段模型链路保持不变。
