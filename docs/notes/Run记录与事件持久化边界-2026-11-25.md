# Run 记录与事件持久化边界

## 本日目标

第四周第 1 天新增 `internal/runstore`，为 Run 记录、运行观测和执行事件建立稳定
的领域模型与存储接口，并提供线程安全的进程内内存实现。

本日没有接入数据库、HTTP 管理接口或 Agent Runtime 自动写入。

## 包职责

```text
internal/configregistry
  -> 管理发布版本、激活版本和配置快照

internal/runstore
  -> 定义 Run、事件、观测和 Store 接口

internal/runstore/memory
  -> 提供 Store 的进程内内存实现

internal/agent
  -> 负责 Runtime 和工具循环编排
```

RunStore 与配置注册中心不是同一个注册中心：

- `configregistry` 保存控制面配置版本和不可变配置快照；
- `runstore` 保存数据面一次 Run 的身份、状态、版本引用和执行事件；
- RunStore 只保存配置版本引用，不复制完整 Prompt、Schema 或模型路由配置。

## Run 生命周期

```text
CreateRun
  -> running
  -> succeeded
  -> failed
  -> canceled
```

Run 创建时必须提供 Run ID、Request ID、Tenant ID、发布版本和开始时间。创建后只能
从 `running` 进入一种结束状态，已经结束的 Run 不能继续追加事件或重复完成。

`FinishRun` 保存最终脱敏观测，包括 Provider、Model、耗时、Token、成本、结构化结果
是否有效和错误分类。

## 事件模型

当前支持：

```text
run.started
model.call
tool.call
tool.result
run.succeeded
run.failed
```

事件通过 `AppendEvent` 追加。事件序号由存储层分配，同一个 Run 内保持递增，调用方
不能覆盖序号。事件中的 Run、Request 和 Tenant 标识必须与 Run 记录一致。

事件只记录：

- 事件类型和发生时间；
- Provider、Model；
- 工具名称和版本；
- 执行状态、耗时和错误分类；
- 参数摘要和结果摘要。

事件不记录完整 Prompt、模型回答、工具参数、工具返回数据或 API Key。

## 深拷贝和并发

`MemoryStore` 使用 `sync.RWMutex` 保护 Run、事件和事件序号状态。查询方法返回
独立副本，调用方修改查询结果不会污染存储内部状态。

通用的 Map 容器复制位于 `internal/clone`。它只复制 Map 容器，不声称能够递归复制
任意嵌套对象；嵌套结构仍由所属领域负责处理。

锁和深拷贝解决的是不同问题：

- 锁保护方法执行期间的并发访问；
- 深拷贝保护方法返回之后的对象所有权。

## 与 Agent Runtime 的边界

本日没有把 `Runtime` 或 `ToolLoopRuntime` 改造成自动写入 RunStore。当前调用链仍是：

```text
Agent Runtime
  -> 配置版本选择和模型/工具执行
  -> Observer 脱敏观测

RunStore
  -> 独立保存 Run 记录和事件
```

后续接入时，应该通过适配器把 Runtime 的最终观测和工具事件转换成 RunStore 模型，
而不是让 RunStore 直接调用模型或工具。

## 与数据库实现的边界

当前 `MemoryStore` 只用于本地测试和演示：

- 数据只存在进程内；
- 进程重启后数据丢失；
- 不提供跨进程一致性；
- 不提供事务、索引、分页和保留策略；
- 不提供完整审计查询。

后续可以增加 `internal/runstore/postgres` 等实现，复用 `runstore.Store` 接口，
而不改变 Agent、工具循环和脱敏数据边界。

## 当前限制

- 尚未接入 PostgreSQL 或其他数据库；
- 尚未接入 HTTP 管理接口；
- 尚未实现用户身份认证、RBAC 和租户成员关系；
- 尚未实现审批系统和完整审计；
- 尚未支持完整模型输入输出重放；
- 不保存 API Key、完整 Prompt 或完整模型回答。
