# 评测与发布复盘边界

第二周第 6 天增加了离线评测、灰度演示、影子运行、发布门禁、回滚关系和历史重放证明。

## 评测层次

评测集位于 `evals/week2-day6.jsonl`，使用 JSONL 保存脱敏样例。每条样例包含场景、
预期结构化结果、是否允许修复、是否模拟模型错误以及是否参与质量门禁。

评测分为两类：

- 功能负向样例：验证非法 JSON、Schema 错误、业务语义错误、模型错误和 Context
  取消是否被正确分类。这些样例会进入错误统计，但预期失败不会被算作候选版本质量失败。
- 质量样例：验证正常回答、拒答和修复后的结构化结果。这些样例才进入成功率、
  结构化成功率、P95 延迟和平均成本门禁。

同一批样例分别使用 `deepseek` 和 `kimi` 两个确定性 Fake Provider 执行。这里的
供应商名称只是路由和元数据身份，不代表真实供应商质量结论。

## 稳定性与脱敏

每条样例默认重复执行 3 次。评测器只对结构化结果和版本元数据生成 SHA-256 摘要，
通过摘要比较重复运行是否一致，不把完整模型回答写入报告。

报告保留：

- provider、release version 和样本数；
- 成功、结构化成功、解析失败和修复次数；
- P50/P95 延迟、Token、成本和错误分类；
- 灰度选择、影子运行、门禁和回滚关系；
- 历史配置快照重放结果。

报告不保留 API Key、完整 Prompt、完整模型回答、真实用户数据或供应商原始错误文本。

## 发布演示

本地演示流程为：

```text
发布 v1
  -> 激活 v1
  -> 发布候选 v2
  -> 租户白名单命中 v2
  -> 主请求执行 v1
  -> 影子请求执行 v2
  -> 候选指标进入 EvaluateGate
  -> block 后显式创建 v3 回滚版本
  -> 查询历史版本
  -> 使用 v1 快照和 Fake Provider 重放
```

候选版本的失败由 Fake Provider 受控注入，只用于证明发布门禁可以阻断退化版本。
`EvaluateGate` 只产生确定性决策，不直接修改 Registry；回滚由演示流程显式调用
`Registry.Rollback`。

## 重放边界

历史重放复制原始 release 的配置快照，并使用同样的确定性 Fake Provider，因此可以
验证版本元数据、结构化结果摘要和成功状态的一致性。

这不等同于真实模型的确定性重放。真实模型输出会受供应商、模型版本、采样参数和
网络状态影响。后续如果要支持生产级重放，需要保存事件、配置快照、依赖录制和
明确的重放模式。

## 当前限制

- 评测和发布状态仍保存在进程内，没有数据库持久化。
- `cmd/eval` 不访问真实模型服务，不执行真实双供应商对比。
- 当前没有 HTTP 管理接口、自动回滚任务或持续评测流水线。
- 评测集规模较小，不能替代后续第 13 周的大规模回归评测。
