# Runnable 组合与灰度边界

第二周第 5 天新增一个独立的 Agent Runtime，用 Eino Chain 串联配置版本选择、
Run 快照、Prompt 渲染、模型调用、结构化输出校验和最终结果格式化。

## Runtime 调用链

```text
请求输入
  -> 灰度选择 active 或 candidate release
  -> 绑定不可变 Run 快照
  -> 渲染 task_analysis Prompt
  -> 调用 ModelCaller
  -> DecodeTaskAnalysis
  -> 渲染 final_answer Prompt
  -> 调用 ModelCaller
  -> DecodeFinalAnswer
  -> 格式化 RunOutput
```

Runtime 使用 `compose.NewChain` 创建类型化 Runnable，但 HTTP 层不依赖 Eino 类型。
现有 `Pipeline` 的 Chain 和 Graph 示例保持不变，Runtime 是面向真实业务状态的独立编排。

## 依赖边界

- `internal/configregistry`：保存不可变发布版本和 Run 配置快照。
- `internal/rollout`：根据租户白名单和稳定流量桶选择 release，不修改发布状态。
- `internal/agent`：负责 Eino Runnable 编排、Prompt 渲染和结构化结果组合。
- `internal/modelgateway`：通过 `ModelCaller` 提供供应商无关的模型调用。
- `internal/structuredoutput`：负责 Schema、业务语义和最多一次修复。
- HTTP Handler：本日不接入 Runtime，现有 `/chat` 和 `/chat/stream` 契约不变。

Runtime 依赖 `ModelCaller` 接口，而不是具体供应商客户端。生产环境可以注入
`modelgateway.Router`，测试则注入确定性的 Fake，因此不会让供应商协议扩散到 Agent
编排层。

## 配置快照与版本元数据

一次 Run 先选择 release，再绑定该 release 的深拷贝。后续激活新版本不会改变已经
绑定的 Run。分析和最终回答阶段分别从快照读取：

- `Prompts["task_analysis"]`
- `Prompts["final_answer"]`
- `Schemas["task_analysis"]`
- `Schemas["final_answer"]`
- `Routes["task_analysis"]`
- `Routes["final_answer"]`

快照中的 provider、model、Prompt 版本、Schema 版本和模型路由版本会传递给
`structuredoutput.DecodeOptions.Metadata`，并保存在 `RunOutput` 的解析报告中。
Runtime 不在代码中写死业务 Prompt，也不把 API Key 放入快照。

## 灰度选择

本地 `rollout.Selector` 使用以下优先级：

1. 租户在白名单中，始终使用候选版本；
2. 有租户时使用 `TenantID`，否则使用 `RequestID`；
3. 对选择键计算 SHA-256，并把结果映射到 `0~99` 桶；
4. `Bucket < Percentage` 时使用候选版本；
5. 其他请求使用当前 active 版本。

选择结果包含版本、是否命中候选、桶值和原因。同一个租户或请求 ID 在策略不变
时会得到相同结果。候选版本必须已经发布，但选择器不会自动激活候选版本。

## 影子运行

`RunShadow` 强制执行候选版本，只进行 Prompt、模型调用和结构化解析，输出标记为
`Shadow=true`。当前 Runtime 没有工具、数据库或外部副作用接口，所以影子运行无法
执行写操作，也不会改变主请求结果。

影子运行失败只通过自身返回值和观测记录体现，不会自动激活候选版本，也不会自动
调用回滚。

## 发布门禁

`EvaluateGate` 根据以下指标产生确定性决策：

- 样本数；
- 成功率；
- 结构化输出成功率；
- P95 延迟；
- 平均成本。

结果为：

- `hold`：样本不足；
- `allow`：达到最小样本且全部指标通过；
- `block`：指标未达到阈值；
- `rollback_candidate`：成功率或结构化成功率为零，建议回滚候选版本。

门禁只产生决策，不直接修改 Registry。后续发布控制流程可以根据决策调用
`Registry.Rollback`，从而把自动动作和评估逻辑分开。

## 观测和安全边界

Runtime 通过 `Observer` 接收请求 ID、租户 ID、Run ID、release、模型、耗时、
Token、成本、影子标记和错误分类。观测不包含 API Key、完整 Prompt 或完整模型
回答。模型错误也只保留稳定的阶段分类，避免把供应商原始错误文本带入业务日志。

## 当前边界

本日没有实现：

- HTTP 灰度管理接口；
- 数据库持久化；
- 工具调用和审批；
- 自动重试、自动降级和自动回滚；
- 真实供应商的线上影子流量。

这些能力需要后续的数据面、控制面和发布流程支持，不能由当前内存实现伪装成生产
保证。
