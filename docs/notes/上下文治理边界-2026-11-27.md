# 上下文治理边界

## 1. 本次范围

第 4 周第 3 天已为 `ToolLoopRuntime` 实现确定、可解释、可观测的本地上下文治理，覆盖工具决策和最终回答 Prompt。普通 `Runtime` 仍是固定两阶段 Chain，没有多轮工具历史，因此不复制这套治理流程。

本次治理只改变**发送给模型的历史投影**，不修改原始执行事实：

- 不修改 `toolLoopState.toolHistory`；
- 不修改绑定的 `ConfigSnapshot`；
- 不修改最终输出中的 `ToolCalls` 和 `ToolDecisionRounds`；
- 不修改授权、重复检测、Executor、工具事件或 Run 状态转移；
- 不增加模型摘要调用、工具执行步数或真实供应商 Usage。

## 2. 上下文策略与版本

`ContextPolicy` 由可信调用方通过 `ToolLoopConfig` 提供，构造 Runtime 时完成校验和默认值填充，之后对所有并发 Run 只读。

| 字段 | 当前默认值 | 含义 |
| --- | ---: | --- |
| `MaxHistoryTokens` | 12000 | 可裁剪工具历史 envelope 的目标 Token 上限 |
| `MaxToolResultTokens` | 2560 | 单个工具 Data 的压缩目标 |
| `KeepLatestResults` | 10 | 优先保留的最新工具结果数量 |

每个字段的 `0` 独立表示使用默认值，任一负数返回 `ErrInvalidContextPolicy`。这些数值是当前本地执行策略，不是生产容量或模型质量结论。

上下文版本格式为：

```text
context.v1:<ReleaseVersion>:h<MaxHistoryTokens>:r<MaxToolResultTokens>:k<KeepLatestResults>
```

默认策略绑定 `v1` 时示例：

```text
context.v1:v1:h12000:r2560:k10
```

版本在快照绑定成功后写入当前 Run 的观测。同一 Run 使用固定发布版本和构造时策略，不读取执行中变化的全局配置。它标识治理算法、发布版本和实际参数，但不替代 `ConfigSnapshot`，也不是新的控制面发布对象。

## 3. 单工具结果压缩

`compressToolResultData` 只处理合法 JSON Data，过程不调用模型：

1. 使用 `json.Compact` 校验并紧凑编码；
2. 按紧凑内容的本地 Token 估算判断是否需要压缩，避免仅因大量空白进行无意义压缩；
3. 未超过目标时返回原始字节的独立副本，不改写 Data；
4. 超过目标时生成包含以下字段的合法 JSON 对象：

```text
compressed       固定为 true
original_tokens  原始 Data 的本地 Token 估算
digest           原始 Data 字节的 SHA-256，带 sha256: 前缀
preview          紧凑 JSON 的 UTF-8 安全前缀预览
```

`preview` 按 Unicode 码点截断，最多保留 `MaxToolResultTokens × 4` 个码点，与当前本地 Token 粗估规则一致。它可能只是紧凑 JSON 的前缀，**自身不一定是完整 JSON**；包含它的外层压缩对象始终是合法 JSON。预览不是模型生成的语义摘要，也不能保证保留任意工具数据中的所有语义重点。

压缩目标是软目标，压缩对象中的版本无关摘要、字段名等固定元数据会额外占用空间，不为凑硬上限而删除。

非法 JSON 继续返回 `ErrToolHistoryEncodingFailed`，不能通过压缩、降级或省略掩盖数据错误。

## 4. 历史 envelope 与保留顺序

治理后的工具历史采用受控 envelope：

```json
{
  "context_version": "context.v1:v1:h12000:r2560:k10",
  "omitted_entries": 0,
  "entries": []
}
```

`entries` 使用显式 Prompt 投影类型，只允许工具名称、版本、状态、错误码、参数摘要、Data 和来源位置进入模型输入，不直接序列化内部历史对象。

每次 Prompt 构建都从原始历史创建新副本，不复用上一轮压缩结果，避免多轮压缩造成累积信息损失。

处理顺序如下：

```text
原始历史独立投影
  → 逐条执行单结果压缩
  → envelope 仍超目标时，从最旧到最新移除非关键旧条目的 Data
  → 仍超目标时，从最旧到最新省略非关键旧条目
  → 输出 context_version、omitted_entries 和保留 entries
```

关键证据包括：

- 最新 `KeepLatestResults` 条结果；
- 失败结果，包括不在最新范围内的旧失败结果。

关键证据不会因历史目标而被降级或省略。被保留条目的工具身份、状态、错误码、参数摘要和 Source 继续保留。用户 Query、通过校验的 TaskAnalysis 和 ConfigSnapshot 不属于可裁剪内容。

因此，历史目标是治理投影的软目标，而不是删除固定元数据或关键证据的硬上限。`omitted_entries` 明确告知模型存在省略，避免把治理后的历史误认为完整历史。

## 5. Prompt Token 统计口径

工具决策和最终回答共用 `renderGovernedToolLoopPrompt`：

- `before`：相同模板和 `context.v1` envelope 下，使用未治理完整历史渲染的完整 Prompt；
- `after`：使用实际治理后历史渲染、真正发送给模型的完整 Prompt。

两次渲染使用相同的原始 Query 和 TaskAnalysis，只替换历史投影。统计包含模板、Query、分析和历史，不只统计 Data。任务分析首次模型调用没有工具历史，不计入本日上下文治理指标。

Token 使用现有 `estimateTokenCount`：非空文本每 4 个 Unicode 码点估算 1 Token，向上取整。该值只用于本地治理观测，不代表供应商真实计费用量。

## 6. Observer、RunStore 与失败语义

Agent 和 RunStore 的最终观测增加五个脱敏字段：

| 字段 | 含义 |
| --- | --- |
| `ContextVersion` | 当前 Run 固定的上下文版本 |
| `ContextBuilds` | 成功完成治理的工具决策和最终回答 Prompt 数量 |
| `ContextTrimmed` | 实际发生压缩、降级或省略的 Prompt 数量 |
| `ContextTokensBefore` | 各次未治理基线完整 Prompt 的 Token 估算之和 |
| `ContextTokensAfter` | 各次实际治理后完整 Prompt 的 Token 估算之和 |

每次渲染成功后立即通过当前 Run 独立的 `runtimeExecution` 累计报告，并使用互斥锁保护。最终由 `snapshotRunObservation` 在同一锁内复制到 RunStore，避免并发更新丢失或双端字段不一致。

如果后续模型调用或结构化解析失败，已经完成的治理指标仍随原有失败观测保留，原有 `ErrorKind` 和 Run 终态不变。如果尚未绑定快照，上下文版本可以为空。

RunStore 写入仍是旁路操作，失败只通过现有 `OnStoreError` 报告，不改变 Runtime 业务返回。本日没有新增 Run 状态、事件类型或状态转移。

## 7. 敏感数据与事实边界

Observer 和 RunStore 只保存上述数值及版本标识，不保存：

- 完整 Prompt 或模型回答；
- 工具参数、原始 Data 或完整工具结果；
- 压缩 `preview`；
- API Key、Capability Token；
- 供应商或工具底层原始错误文本。

参数和结果摘要继续使用既有 SHA-256 脱敏边界。压缩预览只允许进入当前模型 Prompt。

历史治理不删除最终 `ToolCalls`、RunStore 工具事件或配置引用。裁剪的是模型输入副本，不是 Run 事实。

## 8. 并发与限制

`ToolLoopRuntime.contextPolicy` 构造后只读；每个 Run 使用独立历史、执行账本和观测状态。相同输入、策略和发布版本得到相同的治理 JSON、上下文版本和 Token 报告。

当前实现仍有明确限制：

- 本地截断不是语义理解，可能丢失未保留内容中的重要信息；
- 默认策略不是任意模型或生产规模的最优配置；
- 不实现可信度标签、Prompt Injection 拦截或数据流安全策略；
- 不实现 Tape、Checkpoint、完整 Replay、事件回放器或 Fuzz 状态模型；
- 测试全绿不代表第 4 周整周安全、持久化或重放目标已经完成。
