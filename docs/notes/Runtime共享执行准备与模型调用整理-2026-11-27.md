# Runtime 共享执行准备与模型调用整理

## 1. 目标与保留边界

普通 `Runtime` 和 `ToolLoopRuntime` 继续保留各自公开入口和业务语义：

- 普通 Runtime 负责固定两阶段 Eino Chain、正常 Run 和候选版本 Shadow Run；
- ToolLoopRuntime 负责动态工具决策、授权、重复检测、工具执行和最终回答；
- 本次只共享执行准备和受控模型调用，不合并两种 Runtime，也不改变评测调用方。

## 2. 共享执行准备

`internal/agent/runtime_execution.go` 新增内部 `runExecutionOptions` 和 `prepareRunExecution`，统一处理：

1. 在配置选择之前记录开始时间；
2. 解析用户、租户和 Run 三级预算；
3. 创建每次 Run 独立的预算控制器；
4. 校验用户级预算所需的可信 `UserID`；
5. 创建携带 `BudgetViolation` Cause 的总超时 Context；
6. 初始化 `runtimeExecution`、RunStore recorder 和脱敏观测；
7. 将执行账本注入 Context。

`shadow` 同时写入执行状态和观测。普通 Runtime 仍自行处理候选版本强制选择，Shadow 不绑定正常 Run 快照、不写正常 RunStore 终态的边界不变。ToolLoopRuntime 通过轻量 `prepareExecution` 适配共享函数，保持原有 `Run` 主流程简洁。

## 3. 共享受控模型调用

`internal/agent/runtime_model_call.go` 包含：

- `runtimeModelCall`：描述任务、Prompt、阶段错误名称和稳定模型错误哨兵；
- `runtimeModelCallContext`：适配 `ModelCaller`、`runtimeExecution`、`RunInput` 和不可变配置快照；
- `invokeModelWithinBudget`：实现两种 Runtime 共用的预算、超时、MaxTokens、调用记录和 Token 结算；
- 普通 Runtime 与 ToolLoopRuntime 各自的轻量 `callModelWithinBudget` 适配方法。

公共调用顺序保持为：

```text
记录路由
→ BeginModelStep
→ 按 Run 剩余时间收紧 Timeout
→ 按剩余 Token 收紧 MaxTokens
→ ModelCaller.Chat
→ 记录 model.call
→ 记录模型响应与成本
→ 结算真实或估算 Token
→ 返回阶段化错误
```

供应商同时返回响应和错误时，仍先记录并结算已经发生的用量，再返回模型错误。Usage 缺失时仍按当前阶段 Prompt 和实际响应文本进行确定性估算。

## 4. 阶段职责与错误契约

普通 Runtime 的 `callAnalysisModel` 和 `callFinalModel` 已迁移到共享内核，只保留路由、阶段参数和响应保存。错误契约不变：

| Runtime | 阶段 | 预算阶段 | Token 阶段 | 模型阶段 | 稳定错误 |
| --- | --- | --- | --- | --- | --- |
| Runtime | Analysis | `analysis_budget` | `analysis_token_budget` | `analysis_model` | `ErrAnalysisModelFailed` |
| Runtime | Final | `final_budget` | `final_token_budget` | `final_model` | `ErrFinalModelFailed` |
| ToolLoop | Analysis | `tool_loop_analysis_budget` | `tool_loop_analysis_token_budget` | `tool_loop_analysis_model` | `ErrAnalysisModelFailed` |
| ToolLoop | Decision | `tool_loop_tool_decision_budget` | `tool_loop_tool_decision_token_budget` | `tool_loop_tool_decision_model` | `ErrToolDecisionModelFailed` |
| ToolLoop | Final | `tool_loop_final_budget` | `tool_loop_final_token_budget` | `tool_loop_final_model` | `ErrFinalModelFailed` |

结构化输出解析、Repair、工具授权、重复检测和 Executor 调用仍由各自阶段负责，没有进入共享模型调用内核。

## 5. 未改变的范围

- `Run`、`RunShadow`、Runtime 配置和输出等公开契约不变；
- 普通 Runtime 的 Chain 阶段顺序、灰度、Shadow、回滚和历史重跑语义不变；
- ToolLoop 的工具循环、观测、RunStore 和错误收口顺序不变；
- 离线评测 `RuntimeHandle` 和 `RuntimeFactory` 不需要修改；
- 不涉及 HTTP 工具循环接入、Tape、Replay、Checkpoint 或上下文治理。
