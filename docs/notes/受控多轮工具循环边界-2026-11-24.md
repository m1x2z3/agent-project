# 受控多轮工具循环边界

## 本日目标

第三周第 5 天新增 `internal/agent.ToolLoopRuntime`，把任务分析、工具决策、
可信授权、单次工具执行、结果回传和最终回答串成一个受控循环。

本日只实现可测试的本地编排，不修改 `/chat`、`/chat/stream`，不接入 MCP、
数据库、RBAC、审批系统、自动重试或自动降级。

## 调用链

```text
RunInput
  -> 版本选择和 Run 快照绑定
  -> TaskAnalysis
  -> ToolDecision
  -> ToolCallAuthorizer
  -> runner.Executor
  -> Registry.Resolve
  -> tooling.Invoke
  -> Tool.Execute
  -> 工具历史回传
  -> 下一轮 ToolDecision
  -> FinalAnswer
  -> ToolLoopOutput
```

`ToolLoopRuntime` 是循环编排器，不直接调用 `Tool.Execute`。工具执行仍然必须
经过 `runner.Executor` 和 `tooling.Invoke`，因此模型输出不能直接产生副作用。

## 关键边界

- `structuredoutput.ToolDecision` 只表示模型意图，不包含有效授权。
- `ToolCallAuthorizer` 由可信调用方注入工具版本、租户、Run、资源范围、
  Capability Token 和幂等键。
- `runner.Executor` 只负责一次工具执行，不负责决定是否继续循环。
- `ToolLoopRuntime` 负责根据工具结果发起下一轮模型决策。
- `ToolLoopOutput` 只保留脱敏工具调用摘要，不返回完整参数和工具结果原文。
- 默认最多执行 3 次工具调用，并拒绝相同工具、版本和参数摘要的重复调用。

## 观测

工具循环复用 Agent Runtime 的观测结构，记录发布版本、Provider、Model、耗时、
Token、成本、成功状态和错误分类。观测通过 `Observer` 注入，不记录完整 Prompt、
模型原文、API Key 或完整工具返回数据。

成功和失败路径都只提交一次最终观测，避免同一个 Run 被重复统计。

## 当前限制

- 尚未接入 HTTP API。
- 尚未实现 MCP Adapter、数据库持久化、RBAC、审批和用户身份认证。
- 尚未实现自动重试、自动降级、多工具并行或异步 Worker。
- 工具循环使用注入式 `ModelCaller` 和 `ToolCallAuthorizer`，真实供应商调用
  仍由模型网关负责。

## 第三周第 6 天验收边界

第三周第 6 天只对上述本地编排进行离线验收，不改变工具循环的生产接口。
验收覆盖成功链路、结构化解析失败、授权失败、工具解析失败、最终回答失败、
重复调用、最大调用次数、Context 取消和并发运行。

验收同时确认以下执行边界保持成立：

```text
ToolLoopRuntime
  -> runner.Executor
  -> ToolRegistry.Resolve
  -> tooling.Invoke
  -> Tool.Execute
```

错误路径会停止后续阶段，并只提交一次最终观测。最终输出、错误和观测只保留
脱敏元数据，不包含 API Key、完整 Prompt、完整模型输出、完整工具参数或完整
工具返回数据。

验收证据位于：

```text
docs/evidence/2026-11-25/week3-day6.md
```

这份证据基于确定性 Fake Model 和本地测试工具，不代表真实供应商或真实工具的
质量结论。接入生产前仍需要身份、RBAC、持久化、防重放和副作用治理能力。
